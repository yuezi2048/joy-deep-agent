# deep-agent-demo 复盘笔记

> 给未来的自己看：TS / Node 异步核心 + 本次会话踩过的坑。
> 每个结论尽量两句话说完，现场细节都在提交信息里（`git log` 每条都是「现象 → 原因 → 改法」）。

## 一、异步总纲

- **`async/await` 只是语法糖**：底层依旧是事件循环 + 事件回调；它不创造并发，只把横向嵌套改成纵向线性写法，方便用 `try/catch` 统一兜异常。
- **`await` 只暂停当前 async 函数**，不阻塞 Node 进程；事件循环继续跑，别的任务照常推进。
- **并发 ≠ 并行**：单线程靠事件循环交替推进多个任务是并发；多核同一时刻真的同时执行才叫并行。Node 主线程是单线程。
- **阻塞只来自同步代码**：`fs.readFileSync` 会冻结事件循环；回调风格 API 本身是非阻塞的，注册完立刻归还主线程。

## 二、Promise 与 async 的边界

- **Promise 是一张未来兑现的欠条，`resolve` 就是兑现触发器**；老旧回调 API 不能直接 await，要 `new Promise` 并在回调内部 resolve。
- 回调是延后触发的，**回调产生的值只能在回调内部拿到**；工程上可用 `util.promisify` 自动包装，手写 new Promise 是为了看清底层。
- **async 函数里 `return 普通值` 会被引擎自动包成 `Promise.resolve(值)`**，所以再手写 `return Promise.resolve(x)` 属于画蛇添足。
- 判断标准：API 自带 Promise 就直接 await；只有回调 API 才需要适配器。
- 对外口述版：原生回调本身是异步的，可以直接写；连续异步会掉进回调地狱，Promise + await 只是把嵌套改成顺序写法，方便串联多步逻辑、统一捕获异常。
- 本项目的落地：工具调用前串行等待人工确认（`waitForUserConfirmation`），确认通过后再写文件，一次只处理一个。

## 三、本次会话踩的坑

### 1. 正则写死围栏长度 → 文件被截断
AI 在文档里嵌套代码块时会把外层围栏加成 4 个反引号，而正则写死 3 个、内容部分又是惰性匹配，遇到内层第一个 `` ``` `` 就收尾，实测只写入 64 字节。
→ 解析时要捕获开头围栏的反引号数量，并要求结束围栏不短于它。

### 2. 围栏协议无法自证边界 → 换成 `<file>` 标签
模型把内层 `` ```js `` 的闭合写成了 `` ```` ``，解析器只能认为文件块到此结束，后半篇报告全落在块外。
→ 当边界由模型自由书写时，换一个不可能和正文冲突的分隔符，比继续调正则靠谱得多。

### 3. 提示词太模糊 → 模型反问用户
只写「需要写文件时」等于把判断权交给模型，结果同一句请求时写时不写，还反问「要不要保存」。
→ 要写清触发条件（哪类任务必须落盘）；但也不能写太宽——「能成文的都必须落盘」会让子智能体多写出无意义的文件。

### 4. `max_tokens` 截断伪装成「解析丢内容」
上限 4096 时长报告写到一半就没了（11271 字节的文件停在 `## 七`），现象和解析 bug 一模一样。
→ 用 `finish_reason === "length"` 告警，才能把「模型没写完」和「解析丢了」分开。

### 5. 两个 readline 抢同一个 stdin → 确认后主循环卡死
HITL 自建了 readline，它 `close()` 时会把共享的 `process.stdin` 置为 paused（实测 `isPaused: false → true`），而宿主的 rl 只在自身 paused 时才 resume，于是第二个 `你：` 永远等不到输入。
→ 谁拥有 stdin 谁提供 `ask`，工具函数不要偷偷再建一个输入接口。

### 6. 兜底逻辑放错了层
兜底一旦写进解析函数，它返回的就不再是「解析结果」，调用方也分不清文件是模型写的还是兜底生成的。
→ 解析归解析，策略归调用方：`filesWritten` 为空且回复含代码块时，调用侧存一份 `output-<时间戳>.md`，命名一律带时间戳避免互相覆盖。

## 四、比结论更值钱的排查手法

1. **先把原始输出丢给解析函数实测**，确认「有没有东西可解析」再怀疑解析逻辑，能省掉大量方向错误的调试。
2. **最小复现**：把可疑交互抽成十行脚本，在真终端里跑；用管道输入冒充交互会造出假象（`ERR_USE_AFTER_CLOSE` 就是这么来的）。
3. **每个结论都要有反例 + 修复后实测**，真实模型跑一次比读十遍代码管用。
4. **看到「内容不全」先分三类**：模型没写完（token 上限）、解析截断（正则/围栏）、压根没触发协议（提示词）。
5. **提交信息写「现象 → 原因 → 改法」**，下次回看日志就能对上现场。

## 六、零散语法坑

- **`flatMap` = `map` + `flat(1)`，只展平一层**（不像 `torch.flatten` 全量打平）；回调必须返回数组，多分支时类型要统一，单值包成 `[val]`。
- 反过来，在普通 `map` 回调里无脑包 `[]`，只会得到二维数组。
