# ADR-0009：Skill 按触发条件注入，判断权在代码不在模型

- 状态：已接受
- 日期：2026-09-30

## 背景

简历写着「Skill 按触发条件动态注入 Prompt」。原型 `prototypes/deep-agent-demo/src/skill-loader.ts`
的做法是：扫描 `*.skill.md`，把**全部** skill 的 description 与例子拼进 system prompt，
再靠提示词说「当用户输入符合某个技能触发条件时，请主动调用它的 Script」。

两处问题：

1. **判断权在模型**：命不命中由模型读自然语言描述自己判断，行为不可断言、不可复现。
2. **token 随技能数量线性膨胀**：装 20 个技能，哪怕这次一个都用不上，也要为 20 段的描述付费。

## 决策

`src/skills/`：`SKILL.md`（一个技能一个目录）+ 加载器 + 注入渲染。

1. **谁判触发**：代码。触发条件两种写法——纯字符串是**大小写不敏感子串**，`/pattern/flags` 是**正则**。
   `select(input)` 返回命中项；没命中就返回空数组，调用方据此**一个字符都不注入**。
   这是与原型的分水岭，也是「动态注入」这四个字真正兑现的地方。
2. **frontmatter 只支持一个子集**：`key: value` 与 `- item`，不引 YAML 依赖。
   支持得少，但**拼错了会报错**（未知字段、重复字段、缩进异常、非法正则都点名到行）。
   宁可不支持，也不要按某条冷门 YAML 规则静默解析成别的东西。
3. **接缝是 `AgentLoopOptions.augmentPrompt`**：每轮执行前调一次，返回值追加进本次 system prompt。
   core 因此不认识 SKILL.md、目录约定与触发匹配——CONTEXT.md 的「运行时加载，不改主循环」是真的。
4. **渐进披露**：命中的技能注入 name + description + 正文；`references` 只注入**路径清单**与
   「按需 read_file」的提示。正文全量注入会把技能变成新的上下文炸弹。
   路径的坐标系要统一：`SKILL.md` 里相对**技能目录**写（作者不用关心技能装在哪），注入时由
   `SkillRegistry` 换算成**相对工作区**的路径——那正是 `read_file` 的坐标系，否则示例技能给的
   `templates/report.md` 模型根本读不到，「按需读」就成了空话。落在工作区外的原样给出，读不读得到
   由沙箱说了算。
5. **预算硬约束**：单条正文超限按 token 截断并标注；总量超限按顺序保留前面的、如实点名没注入的。
   一条都塞不下时也要说明——返回空串等于宣称「什么都没命中」，那是撒谎。
6. **热插拔**：签名缓存（每个 `SKILL.md` 的 mtime + size）。改、加、删文件后下一轮生效，不用重启。
   带上 size 是因为文件系统的 mtime 精度可能是秒级，同一秒内改两次会撞上。
   已知局限：若在同一时间戳内把内容改成**等长**的另一段，签名不变、不会重载。这是「不读文件就能判断」
   的固有取舍——要绝对可靠就得每次读全文，那缓存也就没意义了。
7. **坏文件不静默**：解析失败进 `problems`（文件名 + 理由），好文件照常加载；重名的技能**全部不加载**
   （重名会让命中结果取决于扫描顺序，那是最难查的一类不确定性）。
   但「加载真的炸了」（IO 错误、配置非法）会向上抛——静默降级会让模型在少了技能的提示下照常答题，
   错得毫无征兆。

## 备选方案

- **把 skill 做成工具**：工具回答「能做什么」，skill 回答「这件事该怎么做」；混在一起会让工具表膨胀，
  而且 skill 需要的是指令文本，不是调用约定。
- **全量注入**：token 线性膨胀，且模型被不相关的技能带偏。
- **让主循环认识技能文件**：目录约定、解析、缓存策略都会渗进 `core/`，单 agent 场景被迫背上这套概念。
- **用 YAML 库**：为一个四字段的 frontmatter 引一个解析器（含锚点、类型转换、多行折叠等语义），
  出错时是「按 YAML 规范解析成功了但你我都没想到」。

## 后果

- 触发行为可断言：测试里逐字断言「未命中的技能文本一个字都不出现在 system prompt 里」。
- 技能是新增的 token 放大点，所以预算与截断必须在结果里可见（和 ADR-0007 的 token 账同一姿态）。
- 注入点有两处：主循环（`AgentLoop`，REPL 用）与子智能体（`SubAgent`，编排层用）。
  子智能体不共享主循环的上下文，所以每步子任务的技能匹配各自算一次。
  Planner 与汇总器不注入：它们的提示词是固定角色定义，再叠 SKILL.md 会让「谁说了算」变糊，
  要扩再扩。
