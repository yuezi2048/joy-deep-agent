# ADR-0008：VFS 沙箱用挂载表 + realpath + 配额

- 状态：已接受
- 日期：2026-09-30

## 背景

简历写着「VFS 沙箱受限写盘」。落到代码里，文件防护只有 `src/security/path-guard.ts`：
单根判定、只做**字面路径**，它自己在注释里承认两处局限——不解析符号链接、没有配额与审计。

原型 `prototypes/deep-agent-demo/src/sandbox.ts` 是反例：

- `isPathSafe` 用 `resolved.startsWith(outputPath)` 判越界，`/workspace/output-evil` 会被当成
  `/workspace/output` 的子路径（字符串前缀漏洞）；
- 读写用 `readFileSync` / `writeFileSync`，冻结事件循环；
- 没有大小上限、没有审计，写完就完了。

## 决策

新增 `src/vfs/`：

```
src/vfs/
├── mount.ts    # Mount（前缀 → ro/rw）、最长前缀优先的挂载表
└── sandbox.ts  # WorkspaceSandbox：resolveRead / resolveWrite / read / write / list / audit
```

1. **挂载表**取代单根：`[{ prefix: '.', mode: 'ro' }, { prefix: 'out', mode: 'rw' }]` 这样的表达
   比「一个根 + 一个例外」更能说清意图。命中规则是**最长前缀优先**，否则专门开的口子永远轮不到。
2. **判定走相对路径**（`path.relative`），不是字符串前缀——原型那条回归用例永久保留。
3. **两道判定**：先按字面路径判挂载，再对「最近的已存在祖先」做 `realpath` 后重判一次。
   第二道是补 `PathGuard` 承认的符号链接局限：`workspace/link -> /etc` 字面看在工作区内，
   realpath 之后不在。为什么对祖先做而不是对目标做：写盘时目标通常还不存在，`realpath` 会直接失败。
4. **写盘配额**（单文件字节 / 累计字节 / 文件数）与**审计**。配额在**落盘之前**判定：
   超限不该在磁盘上留下半个文件，也不该让人去确认一次注定失败的写操作（HITL 的确认是有成本的）。
   文件数按**去重后的文件**算——覆盖写同一个文件不重复占额；审计记路径 / 字节数 / 时间 /
   命中的挂载 / **触发它的工具调用 id**。进程内没有「用户」概念，能确定的就是「哪次调用」，
   所以记 `callId` 而不是编一个 `actor` 出来。
5. **缺省不收窄**：不配就是整个工作区可读写，与接入沙箱之前完全一致；收窄是显式选择
   （`AGENT_WRITE_ROOT`）。理由是不想用一个「更安全」的默认值悄悄改掉既有入口的行为——
   要改就得让人看见、让人点头。
6. **缺省配额是有值的**（1 MiB / 8 MiB / 200 文件），这是与 spec「默认零回归」承诺的一处**有意偏差**：
   缺省不设上限，等于把工作区交给模型的 token 预算去决定，而「受限写盘」正是本能力要交付的东西。
   偏差只命中「一次写超过 1 MiB」「累计超过 8 MiB」这类越界量级，且失败回的是可读理由；
   要绝对零回归，把 `AGENT_MAX_*` 调大即可。
7. `PathGuard` **保留**，作为单根基元：`WorkspaceSandbox` 建立在它导出的 `isWithin` 之上。
   两处并存不是重复：报告落盘（`orchestrator/report.ts`）走 `PathGuard`，路径来自配置而不是模型输入；
   模型能碰的文件工具走沙箱，路径来自模型。

## 边界（必须同时写进 README）

这是**进程内的路径约束**，目的是拦住模型误操作与越界写入，**不是 OS 安全隔离**：
挡不住恶意代码（能跑 `run_command` 的模型本来就有工作区权限）。
另外沙箱只管辖内置文件工具；`run_command` 走的是另一条路（命令白名单 + `cwd`），
它的写盘不在这一层里——这条边界不写清，就等于把「沙箱」讲成了它做不到的事。

## 备选方案

- **只扩 `PathGuard`**：挂载表、配额、审计塞进一个类会让「单根判定」这个干净的基元变成杂物间。
- **上容器 / namespace**：那是对抗恶意代码的隔离，与「约束模型误操作」是两件事，成本也差一个量级。
- **只做 realpath，不做配额**：「受限写盘」里的「受限」不只是路径，量也是；没有上限的写盘等于把
  工作区交给模型的 token 预算去决定。

## 后果

- 内置工具变成薄适配层，配额与审计只有一份计数（都在 `WorkspaceSandbox` 上）。
- 口径变化：`write_file` 的返回从「字符」改成「字节」——配额是按字节算的，两处口径必须一致。
- `write_file` 的越界/超限一律是**可读反馈**回灌给模型，不抛穿循环（沿用 ADR-0002 的姿态）。
- `ToolDefinition.requiresConfirmation` 从布尔扩成「布尔或按参数判定的函数」：`write_file` 用`canWrite()` 先做一次只读预检，注定失败的写入不弹确认。HITL 是**有成本**的，让人排队去拒一件不会成功的事，等于把「拒绝」伪装成「等待授权」。
- 触发条件：真需要对抗恶意代码时，按 ADR-0001 的出口把沙箱换成容器实现，调用方零改动。
