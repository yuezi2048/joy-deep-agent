# ADR-0001：包划分用单包 `src/`

- 状态：已接受
- 日期：2026-09-30

## 背景

`CONTEXT.md` 的「待定」里挂着「Harness 的模块边界与包划分（单包 `src/` 还是 `packages/*`）」。简历口径要求的是 NestJS 的 Module/Provider 依赖注入分层（编排 / 工具 / 模型 / 持久化），那说的是 **NestJS 模块边界**，不是 pnpm 包边界，两者不必绑定。

仓库当前是单人项目，三份原型刚冻结，真正的实现一行都还没有。模块边界尚未被真实需求压出来，此时切 `packages/*` 只能靠猜。

## 决策

单包，根目录 `src/`，用目录分层：

```
src/
├── core/        # AgentLoop、消息与状态类型
├── providers/   # 模型供应商适配
├── tools/       # 工具注册表与内置工具
├── robust/      # 8 类鲁棒性中间件
├── memory/      # Memory / Checkpoint 持久化
├── nest/        # NestJS 模块、控制器、SSE
└── index.ts
```

跨层引用一律走 `src/<layer>/index.ts` 的公开出口，层内文件不对外暴露。这条纪律是将来能零成本拆包的前提。

## 备选方案

- **pnpm workspace + `packages/*`**：边界清晰、可独立发布。但当前模块边界会频繁变动，提前拆包只增加改动成本与构建复杂度。
- **NestJS 模块即边界，不做目录约束**：省事，但会让 `robust/` 和 `core/` 互相直连，正是原型里最乱的部分。

## 后果

- 改动成本最低，符合「先把东西做出来」的当下目标。
- 代价：`src/` 内没有编译期的依赖隔离，只能靠约定和 lint 约束。
- 触发条件：当某一层被第二个消费方（例如独立的 CLI 包）复用时，按 `src/<layer>/index.ts` 的出口拆成 `packages/*`，不需要重构调用点。
