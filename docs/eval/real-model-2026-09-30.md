# 真模型 smoke 记录（2026-09-30）

> 这份文件记的是**用真实模型跑通链路**的记录，**不是评测**。评测（`pnpm eval`）仍然是确定性假模型驱动，
> 原因见下一节。真模型跑一次的作用是：验证「换真供应商」这条路是通的，并暴露假模型测不到的问题。

## 为什么评测不换成真模型

`src/eval/scenarios.ts` 里的故障注入是**剧本的一部分**：注入 429 之后模型会不会重试、重试几次、
何时放弃，都由 `ScriptedModel` 决定；恢复成功率与恢复时间只有在**注入点与反应都可控**时才可复现。
换成真模型，注入点仍然可控（故障在工具 / 供应商层注入），但模型侧的反应不可控——
同一场景两次跑出不同的尝试次数，指标就成了随机数，CI 门禁会变成掷骰子。

所以两者定位分开：

- `pnpm eval`（假模型）：防护层的**确定性回归**，回答「防护还有效吗」，进 CI。
- 真模型 smoke（本文件）：回答「真供应商链路通不通、真模型会不会踩到假模型没覆盖的地方」，不进 CI。

## 观察

1. 规划一次解析成功（`planSource: planned`），没有触发降级；汇总也是模型汇总（未 `degraded`）。
2. 汇总器在真模型下**主动如实标注了「未覆盖的点」**（报告正文列出两条超出「三句话」约束的内容），
   说明「如实标注缺口」这条约束在真模型上生效，而不只是在假剧本里被写死。
3. 主循环这条路上，模型自己选了工具、参数正确、一次调用拿到结果后收尾（2 步 / 1657 token）。
4. **只有真跑才暴露、假模型测不到的两个问题，都已修**：
   - `pnpm run report -- "<目标>"` 里的 `--` 被 pnpm 原样传给脚本，目标变成 `-- 用三句话…`。
     修法：入口只剥掉**首个** `--`（`parseGoal`，含单测；npm 会自己剥、pnpm 不会，两种写法都要能用）。
   - 管道输入跑完 / Ctrl-D 时，readline 会带着挂起的 `question` 一起关闭，CLI 打「启动失败：readline was closed」
     并以退出码 1 结束。修法：把这种情况当正常退出，不打栈、不给非零退出码。
     这两条都不在模型行为里，而在**入口与终端**里——正是假模型覆盖不到的地方。

## 局限（别把这份记录当评测读）

- 样本只有 2 次，目标很小（单步 / 两轮），不能代表长链路表现。
- 没有注入任何故障：真实网络超时、限流、502 下的**恢复时间依然没有数据**。
- 假模型评测的结论（完成率 11%→100% 等）**不因这份记录而改变**，两者回答的是不同问题。
